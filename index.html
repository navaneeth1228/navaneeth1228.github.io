I work across the whole life of a data product: ingesting and normalizing messy industrial data, designing the relational model underneath it, building the APIs and React frontends on top, and wiring in event-driven automation that keeps the whole thing current without anyone touching it.

I hold an M.S. in Engineering Science (Data Science) from SUNY Buffalo and a B.E. in Computer Science (AI & ML). I care about systems that are tested, containerized and deployable — not notebooks.

PIPELINE ENGINEERING · ORCHESTRATION · SELF-HOSTED INFRA

Automated Job-Application Pipeline

A scheduled 26-node n8n microservice pipeline that eliminates a daily manual workflow end to end: it retrieves live postings, generates tailored PDFs through a Gemini-backed keyword-extraction agent rendered to LaTeX, and delivers them unattended at 7 AM.

  • Self-hosted the Docker-containerized n8n instance on a Linux VPS rather than local Docker Desktop, removing the dependency on a developer machine being powered on for scheduled triggers to fire.
  • Solved OAuth 2.0 against Google APIs — which reject raw IP addresses as redirect targets — by mapping the VPS to a stable DuckDNS hostname that survives IP changes without re-registering credentials.
  • Prevented duplicate processing and redundant API spend with a two-tier deduplication layer: in-run URL dedup plus a Supabase (PostgreSQL) persistence check issuing lookups concurrently via Promise.all, backed by a job-history table keyed on posting URL.
  • Handled long-running external jobs with an asynchronous polling loop (submit → status-check → conditional wait-and-retry) against the Apify Actor REST API instead of blocking on fixed sleeps.
  • Hardened against upstream data-quality issues with a defensive parsing layer — multi-key field fallbacks, HTML stripping and entity decoding, recency and content-length filters — rejecting malformed records before downstream processing.
